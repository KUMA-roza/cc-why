# 添削モード (tensaku) — 人が本文を直接書き換えて、完成形を返してもらう

長文 (記事・README・レポート) を人に直してもらう時に使う。指摘だけもらって agent が直すなら指摘モード (`../shiteki/`)、本文そのものを人の手で書き換えてもらうならこちら。

## 1. 編集画面を作る

```bash
python3 assets/tensaku/build-sheet.py <記事.md> <label> "<タイトル>" -o ./akapen/<label>.html
# 例
python3 assets/tensaku/build-sheet.py docs/intro.md intro-01 "はじめに (下書き)" -o ./akapen/intro-01.html
```

- `label` は回答の 1 行目「【赤ペン回答】intro-01」になる短い名前。同じ記事を 2 往復するなら `intro-02` のように番号を進める
- 出力は HTML 1 枚。file:// で開けて、外部ネットワークは要らない (python3 の標準ライブラリだけで動く)。`../akapen-serve.py open` で http://127.0.0.1 から開くとボタンが [送信] になり、完成形が中継に直接届く (貼り付け不要)
- 記事に HTML コメントがあっても壊れない (画面には出ないが、完成形には位置ごと残る)

## 2. 人に開いてもらう (案内文の例)

直接送信 (既定): `python3 "<この skill のディレクトリ>/assets/akapen-serve.py" open ./akapen/intro-01.html` で中継を立ててブラウザを開き、agent は同スクリプトの `wait ./akapen/intro-01.html` (Bash timeout 600000、exit 3 なら繰り返す) で回答を待つ。

```
下書きを添削用の画面にしました。ブラウザで開いています:
  http://127.0.0.1:<port>/intro-01.html

- 直したい段落をクリックすると入力欄が開くので、書き換えて「確定」してください (段落の追加・削除もできます)
- 全体への注文はいちばん下の欄 (記事の下) に書いてください
- 直し終えたら右上の [送信] を押してください。完成形がこちらに直接届きます (貼り付け不要)。
  直す所が無ければそのまま押してもらって構いません
```

貼り戻し (予備。python3 が無い環境、または file:// で開いた時):

```
下書きを添削用の画面にしました。ブラウザで開いてください:
  file:///path/to/akapen/intro-01.html

- (上と同じ)
- 全体への注文はいちばん下の欄 (記事の下) に書いてください
- 直し終えたら右上の [貼り付ける文章を作る] を押してください。回答がクリップボードに入るので、
  このターミナルに貼って Enter してください
```

画面の中でできること: 段落クリックで編集 (Markdown 入力 + 追従プレビュー)、語単位の赤 (消した / 足した) の表示、段落の追加・削除、「完成形」「差分」タブでの通読、「ソース全体」タブで記事全文を 1 つの欄で直す、全体への赤ペン (自由記述。「直す」タブの末尾と回答パネルの 2 か所にあり、同じ内容)。段落を消して節が空になると、削除の行に「この節は空になります」と出る (見出しも消すかは人が決める)。下書きはブラウザ内に保存されるので、途中で閉じても続きから直せる。

## 3. 開催中は記事ファイルを変えない

編集画面には、作った時点の記事が丸ごと焼き込まれている。人が直している間に agent 側で記事ファイルを書き換えると、戻ってくる完成形がその変更を含まず、書き戻しで agent の変更が消える。直したくなったら人の回答を待ち、反映してから次のシート (`intro-02`) を作る。

## 4. 回答が届いたら (貼られたら) agent がやること

届くテキストの形 (直接送信では `wait` の stdout、貼り戻しではターミナルに貼られる。正式な定義: `references/reply-format.md`):

````
【赤ペン回答】intro-01
全体への赤ペン: <自由記述。無ければこの行は無い>
## 添削
- 段落 2: 「小さな工夫を」→「小さな工夫を三つ」
- 段落 5: (削除)
- 段落 7: (追加) 「新しい段落」
```markdown
<完成形 Markdown 全文>
```
---
上の回答を反映して作業を続けてください。お任せの項目は推奨案で確定してください。
````

1. 「完成形 Markdown 全文」を、そのまま元の記事ファイルへ書き戻す (コードブロックの中身が完成形。無編集の段落は元の記事と逐語一致している)
2. 「段落 N: …」の差分行は、人が何をどう変えたかの要約。書き戻しには使わず、意図を読む材料にする (番号は元の記事のブロック番号 = 画面の b002 なら段落 2。追加の番号は完成形での位置)
3. 「全体への赤ペン」は、完成形に含まれていない要望 (方針・追加で直してほしい所)。反映してから続ける
4. 無編集なら `## 添削` の下は `- 変更なし` の 1 行。完成形は元の記事と同じなので書き戻し不要
5. 貼り付けが長すぎる時のために画面には「完成形 .md をダウンロード」ボタンもある。人がそちらを使った場合は、渡されたファイルの内容を記事ファイルへ書き戻す

## ファイル

| ファイル | 役割 |
|---|---|
| `build-sheet.py` | 記事 Markdown → 編集画面 HTML。`--help` で引数の説明 |
| `template.html` | 編集画面の土台。`build-sheet.py` が記事・label・タイトルを焼き込む。改造しても【赤ペン回答】の形とボタン文言 (「貼り付ける文章を作る」「送信」) は崩さない |
| `../akapen-serve.py` | 直接送信のローカル中継 (`open` / `wait` / `status` / `stop`)。3 モード共通 |

# 文章のきまり — 図解ページの解説文

手順 2 (content.json) で守り、手順 4〜5 で見直す基準。読者像は design.json の reader / reader_knows で決まる。

## 大原則

1. **目標は「自然に書かれた良い技術ブログ」。** 定型部品の組み合わせで読みやすくはならない。
2. **深さは欲しい、冗長は要らない。** 短さ自体に価値はないが、事実を足さない文は 1 文でも冗長。
3. どのきまりも「多いほど良い」と読まない。

## 3 つの関門 (1 つでも落ちたら書き直し)

- **比喩の関門**: 読者がすでに知っている概念 (reader_knows) を比喩に置き換えない。かえって理解がずれる。比喩は読者が言葉を持たない概念だけに使い、未知の概念には初出で 1 文の定義をつける。
  - 悪い例: context window を「作業机」と言い換える。
- **実在ブログの関門**: この文体・このレイアウトの記事が、良質な個人技術ブログとして実在しそうか。評論調は落ちる。
- **「なぜ?」3 問の関門**: 主要な結論 3 つに「なぜ?」と問い、紙面の言葉だけで 2 問以上に答えられるか。同語反復や「重要だから」型の答えしか無ければ不合格。

## 段落

- 1 段落 1 トピック・2〜4 文・120 字前後。200 字を超える段落を続けない。
- 段落の並びで因果の鎖をたどる。
- **本文段落の中では禁止**: 番号リストの本文代わり・「結論:」等のラベル語・キーワード太字のばらまき・コールアウトの積み重ね。素の段落が基本形。
- テンプレートの部品 (kicker・結論ボックス・3 行解説・コールアウト 1 箱・キャプション) は正式な部品なので、この禁止に当たらない。

## 見出しを水増ししない

- **本文の文を見出しにしない**: 言い切りの文をカード見出し・サブタイトル・太字のリード行に掲げない。カード見出しは体言止め・25 字以内の区分名 (良い例: 「残した部品 / 外した部品」)。カードや対比レイアウト自体は歓迎。
- **節見出しの上にラベル帯を置かない**: 「前提 / 実験 / 原則」のような意味ラベルも、「SECTION 01」のような番号も、読み手に何も足さない。
- **kicker を埋め草にしない**: 「題材名 + ジャンル語」だけで埋めない。kicker は紙面の性格 (実測 / 入門 など、中身が裏づけるもの) と主題の文脈を運び、title に無い情報を足す。
  - 悪い例: 「SQLITE WAL モード / 技術解説」 良い例: 「プロセス管理の実測メモ」「トークンバケット / 固定窓カウンタとの比較」

## 文体 (技術メモ調)

- 短い平叙文。1 文に 3 つ以上の情報を入れない。文を割ったら割れ目に関係語 (だから / ただし) を置く。助詞は省かず、ぶつ切りの文も避ける。
- 主語は動作主にする。「〜性」「〜こと」を主語にしない。
- 「〜のではない。〜だ」「単なる〜ではない」型の反転と、否定の連打を使わない。
- 決まり文句を使わない: 「理由は〜にある」「〜に他ならない」「本質」「まさに」など。
- **直訳調にしない**: 怪しい文を英語に戻し、英文の方が収まりが良いなら書き直す。目印は「〜し直す / 〜し続ける」「〜についての仮定」「どの〜がまだ〜か」「〜ごとに」の多用で、**1 文に 2 つ以上あれば不合格** (悪い例: 「どの仮定がまだ生きているかを部品ごとに試し直す」)。禁止語の表ではなく、文の型で判定する。
- 括弧を含む文は 1 割以下。文の長さは中央値 20〜55 字・最大 80 字 (render.js が検査)。

## 密度

- すべての文が新しい事実か仕組みを足す。言い直し・意味づけだけの文 (「この非対称が狙いになる」型)・件数予告だけの文は冗長。深く書くとは仕組みを 1 段掘ることで、言葉を増やすことではない。

## 結論と因果

- 冒頭 1〜2 文で主張を言い切る。図解ページでは「結論:」ボックスに入れ、実数の太字は 3 箇所まで。
- 主要な主張ごとに「なぜそうなるか」の仕組みを紙面の中で説明し切る。
- 読者の次の疑問 (例外は / コストは) には「〜では? と思うかもしれない。実際は〜」で先回りしてよい。毎回の儀式にはしない。

## 場所ごとの書き方

- 図の中のラベル: 体言止め・20 字以下・1 ラベル 1 動作。図の中に完全な文を書かない。
- キャプション: 1〜2 文・各 40 字以下で、何を見るかを書く。
- 本文: 完全な文だけ。図の外に体言止めを持ち出さない。

## 見直すときの注意

- 点数より評価のコメントを優先して読む。AI のチェックは評論調・造語・因果の抜けを見逃しやすいので、3 つの関門を毎回そのとおりに実行する。
